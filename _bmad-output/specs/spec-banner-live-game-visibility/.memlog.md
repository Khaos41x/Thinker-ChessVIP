---
topic: Banner visibility only during active Chess.com matches
updated: 2026-10-17T22:09
---

- (direction) The Thinker Chess banner must appear only during an active match and must be hidden throughout game review.
- (capability) CAP-1: Banner visibility follows one centralized active-match predicate across mount, resize, reconciliation, and route-watch paths.
- (capability) CAP-2: SPA transitions hide the banner immediately on analysis/review, post-game, lobby, puzzle, and other non-match states and restore it on an active live game.
- (constraint) The /analysis/game/live/.../review route is always banner-ineligible.
- (constraint) Visible post-game evidence such as Game Review or a game-over root makes the banner ineligible even when the URL still resembles a game route.
- (constraint) No CSS rules, banner markup, geometry, menuHtml, panel layout, or DOM-injection topology may change.
- (decision) Introduce shouldShowThinkerBanner as the sole visibility gate and call it before every display flex assignment, including fallback and watchdog recovery.
- (decision) Keep the banner mounted while ineligible and set display none so SPA navigation can restore it without remounting.
- (note) Current cause: route support and banner geometry are separate; positionThinkerBannerFallback, positionThinkerBannerShell, nested updateBannerPosition, and the shell watchdog can each re-show the banner without a gameplay-state check.
- (note) Hermetic tests cover active /game/live visibility, /analysis/.../review suppression, post-game suppression, /play/online lobby suppression, puzzle suppression, Ghost Mode, and SPA transitions.
- (event) Coherence validation passed with two testable capabilities and explicit visual-scope constraints.
- (event) Preservation validation passed: the user request is fully represented without changing layout or styling.
