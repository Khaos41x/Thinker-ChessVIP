- `core/rating_tracker/service.py`, `process_account`: provider categories are dereferenced with `response.body.get("chess_" + mode, {}).get("last")` before validating their type. A valid JSON response containing `{"chess_blitz": []}` raises `AttributeError`; `_run` does not catch it, so the only worker dies and `start()` cannot replace the non-null worker reference. Add a recorded malformed-category fixture and require an explicit provider error followed by successful processing of another account.
- `core/rating_tracker/service.py`, `_rebuild`, and `goals.py`, `evaluate`: only the latest selected current observation is evaluated. A baseline of 1900, target 2000, and subsequently published complete ordered history of 2010 then 1990 never records the verified earlier crossing. Add this sequence with dates after goal creation and require one historical completion backed by the 2010 observation, while retaining 1990 as current.
- `core/rating_tracker/service.py`, `patch_goal` and `ingest_dom`: resume immediately restores an evaluable state but does not invalidate the existing eligibility/cache validation or record a required post-resume validation generation. Before its scheduled worker runs, a DOM ingest calls `_rebuild`, which can evaluate against still-valid pre-resume public evidence. Test pause/resume while another category keeps the account monitored, then inject DOM evidence before any provider request; no completion or advisory should be emitted until revalidation completes.
- `core/rating_tracker/service.py`, `_ingest_archive`: matching an archive game unconditionally deletes its `chesscom:unknown:{id}` pending row. Numeric equality does not resolve an unknown namespace when the same account has both live and Daily records with that number. Supply both namespace candidates in opposite arrival orders and require the unknown reference to remain pending until category or other independent evidence resolves it; retain an explicit alias rather than silently discarding the ingress reference.
- `core/rating_tracker/service.py`, `_ingest_archive`: the new `complete_modes` guard does not cover all skip branches. A matching standard rated category record with a future `end_time`, or a malformed nonboolean `rated` value, executes `continue` without discarding that mode's completeness. Place that record between valid anchors and verify that the surrounding rating difference is never inserted as `single-game`; all excluded potentially relevant records must break the completeness proof.
- `core/rating_tracker/service.py`, `create_goal` and identity processing: an account created while `player_id` is absent is permanently keyed by username. When its profile later supplies a stable ID, polling does not promote ownership, while creation of another category with the now-verified ID fails `IDENTITY_CONFLICT` against the old username mapping. Test unresolved creation followed by same-account verified identity; promote references transactionally or expose an explicit resolvable conflict instead of permanently blocking further goals.
- `frontend/rating_tracker/external.js`, threshold edit conflict handling: a 409 leaves `.rt-edit` mounted with the captured old `goal.revision`; polling calls `render`, which immediately returns while that form exists. The message asks the user to review the latest values, but the latest revision is never displayed and resubmission repeats the conflict. Use two tabs editing the same goal and require the losing tab to reload current state while preserving or explicitly reconciling its draft.
- `core/rating_tracker/repository.py`, `service.py`, and migrations: no retention/pruning implementation exists. Every distinct DOM rating and public correction is retained indefinitely, and `_rebuild` reloads the complete observation history on each ingest. Implement the planned bounded retention with surviving evidence anchors, document it in Settings, and test that pruning leaves completion references valid and rebuild work bounded.
- `core/rating_tracker/routes.py` and `service.py`: there is no account/goal deletion operation, although the approved plan requires user removal with transactional cache/outbox/job cleanup. Archive retains public identity, observations, cached provider bodies and notifications permanently. Provide deletion with explicit targets and generation invalidation, and test that an in-flight response cannot recreate deleted data.
- `core/rating_tracker/public_client.py`, `request` and `stop`: `timeout=10` is a socket-operation timeout, not an overall response deadline, and `stop()` only sets a flag checked after the blocking body read. A provider that keeps streaming below the per-read timeout can hold the sole acquisition worker beyond the bounded join, so shutdown does not actually cancel HTTP work. Add a slow-stream fixture and enforce an overall deadline plus cancellation of the active response.
