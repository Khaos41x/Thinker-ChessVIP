## Intent

**Problem:** The Phase 2 pipeline is hermetic but cannot yet launch the real calibration campaign: its runner rejects concurrency above one, no immutable real-engine schedule exists, and the VM has not been measured under the intended load.

**Approach:** Prepare an official Stockfish 19 and 8moves_v3 environment, add deterministic four-pair execution, generate an executable Stage 1 manifest plus data-driven Stage 2/3 manifest builders, and perform a short 500 ms/move warmup preflight without starting the long tournament.

## Boundaries & Constraints

**Always:** Use official upstream assets and record SHA-256 hashes; keep Threads=1, Hash=128, MultiPV=1, Ponder=false, no tablebases, Clear Hash plus isready per move, fixed 500 ms/move, and at most four concurrent pairs; preserve deterministic result order, pair-atomic immutable writes, resumability, and existing Phase 1/2 schemas; make Stage 2/3 opponent selection depend on prior measured estimates; keep downloaded binaries, corpora, and tournament output out of Git.

**Ask First:** Starting Stage 1 or any long tournament, changing the 500 ms control, lowering the statistical gates, activating a produced artifact, or publishing/pushing changes.

**Never:** Claim the Stockfish UCI_Elo number is an exact FIDE/Chess.com rating; assign Stage 2/3 opponents using an unmeasured Komodo heuristic; use Depth or Nodes as strength controls; commit Komodo, Stockfish, corpus archives, raw PGNs, or generated match records.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|----------------------------|----------------|
| Concurrent run | Valid plan with concurrency 1–4 | Execute up to that many independent pairs and return records in manifest order | One pair failure is encoded by existing game failure semantics; orchestration exceptions fail the command |
| Resume | Some pair JSON/PGN files already valid | Validate and skip completed pairs while executing only missing work | Missing, conflicting, or tampered companion file fails closed |
| Stage 1 preparation | Verified engines and 8moves_v3 | Deterministic pilot manifest covering sampled Skills and the Stockfish ladder | Hash, UCI option, corpus, or schedule mismatch aborts generation |
| Stage 2/3 preparation | Prior-stage estimates | Select nearest measured references and emit the next immutable schedule/config | Missing Skills, unbounded estimates, or out-of-range references are rejected |
| VM preflight | Komodo, Stockfish, 500 ms, workers 1 and 4 | Warm engines, report per-engine NPS and contention drift, recommend safe concurrency | Unsupported UCI option, timeout, or excessive drift produces a nonzero verdict |

## Spec Change Log

## Design Notes

The benchmark scale is explicitly a protocol-local proxy: `Stockfish 19 UCI_Elo at fixed 500 ms/move on the declared Xeon envelope`. Stage 1 spans the full ladder coarsely; Stage 2 and Stage 3 are generated only after measured estimates identify the nearest connected reference for every Skill. Four pairs mean four active searches at a time because each game alternates engines, while each engine remains single-threaded.

The accepted mixed-residency Skill-25 preflight kept four Komodo and four Stockfish processes alive together. It measured pooled loaded NPS of 1,104,184.61 for Komodo and 588,081.31 for Stockfish at four workers, with isolated-to-loaded degradation of 9.34% and 0% respectively. The official Stage 1 manifest is `benchmark-runs/official-v1/stage1/manifest-final.json`, contains 1,320 opening pairs / 2,640 games, and is intentionally ignored by Git together with downloaded binaries, corpora, and raw campaign output. Its environment and baseline are derived from the passing preflight report rather than accepted as independent CLI values.
